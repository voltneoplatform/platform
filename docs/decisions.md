# Technical decisions

Business decisions live in the Foundation's Decision Log (D1–D52). This file
records technical choices made while building, so they are not changed silently.
Status labels follow the project convention: CONFIRMED (founder decided),
PROPOSED (Claude recommends), ASSUMED (working assumption).

| #   | Decision                                                                                                                                                                                                                                                                                | Why                                                                                                                                                                                                                                                                                                        | Status                                     |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| T1  | TypeScript everywhere: NestJS, PostgreSQL + Prisma, BullMQ/Redis, Next.js, React Native (Expo), one pnpm monorepo                                                                                                                                                                       | Founder decision, 22 Oct 2026                                                                                                                                                                                                                                                                              | CONFIRMED                                  |
| T2  | NestJS 12, Prisma 7.10, Next.js 16, React 19, TypeScript 5.9, Node.js 22.12+                                                                                                                                                                                                            | Current stable releases. TypeScript 7 (the new native compiler) is not adopted yet because NestJS depends on legacy decorator metadata and that combination has not been verified for this project; ts-jest and other tooling also still declare TypeScript below 7. Prisma 8 is still a release candidate | PROPOSED                                   |
| T3  | The API compiles to CommonJS while NestJS 12 ships as ES modules; Node.js 22.12+ loads them natively (`require(esm)`)                                                                                                                                                                   | Keeps Prisma's generated client and tooling simple; no runtime cost                                                                                                                                                                                                                                        | PROPOSED                                   |
| T4  | Vitest with SWC for API tests (not Jest)                                                                                                                                                                                                                                                | Jest on Node 22 cannot load ES-module-only NestJS 12; SWC emits the decorator metadata Nest needs                                                                                                                                                                                                          | PROPOSED                                   |
| T5  | Prisma 7 with the `pg` driver adapter and `prisma.config.ts`                                                                                                                                                                                                                            | Prisma 7's supported setup; no native query engine to ship                                                                                                                                                                                                                                                 | PROPOSED                                   |
| T6  | Rules Prisma cannot express (check constraints, the append-only audit trigger) are added by hand at the end of migration files. CI applies all migrations to a fresh database with `prisma migrate deploy` and fails if `prisma migrate diff` finds any difference from `schema.prisma` | Keeps the database as the last line of defence while proving migrations and schema never drift                                                                                                                                                                                                             | PROPOSED                                   |
| T7  | Staff sign in with a 6-digit one-time code by SMS or email; no passwords                                                                                                                                                                                                                | Spec section 7; field staff use phones. Codes: 5-minute expiry, 5 attempts, single use, HMAC-hashed and bound to the challenge, 30-second resend cooldown                                                                                                                                                  | PROPOSED                                   |
| T8  | Access token (JWT, HS256, 15 minutes) plus rotating single-use refresh token. Reuse of a used refresh token revokes the whole login. Idle limit 30 minutes, absolute limit 12 hours                                                                                                     | Spec section 7 (admin sessions expire after inactivity). Short access tokens limit damage from a leak                                                                                                                                                                                                      | PROPOSED; idle and absolute limits ASSUMED |
| T9  | The admin panel receives the refresh token only as an httpOnly, SameSite=Strict cookie scoped to `/v1/auth`, and calls the API through its own origin. Apps receive it in the response body for secure device storage                                                                   | Page scripts can never read the refresh token                                                                                                                                                                                                                                                              | PROPOSED                                   |
| T10 | Every authenticated request re-checks the session and the staff member's current role in the database                                                                                                                                                                                   | Logout, deactivation and role changes apply at once rather than when a token expires                                                                                                                                                                                                                       | PROPOSED                                   |
| T11 | Roles and permissions are defined in code (`packages/shared/src/roles.ts`) for the MVP                                                                                                                                                                                                  | Spec says roles are configurable; a database-backed role editor can be added later without changing call sites, because everything checks permissions, not role names                                                                                                                                      | PROPOSED                                   |
| T12 | Field roles (agent, technician, recovery) cannot sign in to the admin panel; head-office roles cannot use the Field App                                                                                                                                                                 | Matches the "Uses" column in spec section 2. Until the Field App exists (M5), head office does field steps from the admin panel as the spec allows                                                                                                                                                         | PROPOSED                                   |
| T13 | OTP delivery sits behind an adapter: `log` (development), `memory` (tests). The API refuses to start in production without a real provider                                                                                                                                              | No SMS/email provider chosen yet (founder decision before M2 goes live)                                                                                                                                                                                                                                    | PROPOSED                                   |
| T14 | The admin panel uses neutral placeholder design tokens in one CSS file                                                                                                                                                                                                                  | The Brand Kit (Phase 3) does not exist yet; replacing the tokens restyles every screen                                                                                                                                                                                                                     | ASSUMED                                    |
| T15 | Code is formatted with Prettier and checked in CI; a linter (ESLint) is added in M1                                                                                                                                                                                                     | Keeps M0 small                                                                                                                                                                                                                                                                                             | PROPOSED                                   |
